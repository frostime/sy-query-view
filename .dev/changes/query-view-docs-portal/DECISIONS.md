# 小型实现决定

本文件只记录执行过程中不会改变用户行为、内容来源、任务范围或关键架构，但值得让后续执行者知道的局部决定。原则性变化应先询问用户，并更新 `TARGET.SPEC.md` 与 `graph.md`。

每项简要记录：

```markdown
## YYYY-MM-DD — <决定>

- 任务：<task slug>
- 决定：<采用什么>
- 原因：<为什么>
- 影响：<涉及哪些局部文件或行为>
```

## 2026-08-11 — 文档资源与 README 附录

- 任务：`define-doc-structure`
- 决定：将根 `assets/` 的 76 张文档图片迁至 `docs/assets/`；保留 README 的完整类型声明附录；外部 README 打包副本继续使用现有 `@main` 图片改写。
- 原因：文档源与其图片放在一起，插件内文档站完全读取本地打包材料；类型附录保持现有外部读者体验。外部 README 的远程图片不参与插件内文档站，因此不阻塞离线与版本一致性。
- 影响：后续文档任务移动资源并更新生成器、README 路径和 Vite 图片改写前缀；版本 tag 固定图片地址延期。

- 任务：`write-human-docs`
- 决定：生成的 README 暂时继续包围 API 参考与类型声明附录的 `REFERENCE-START/END` 标记；docs 源页面不写这些标记。

## 2026-08-11 — README 同步检查的换行规则

- 任务：`write-human-docs`
- 决定：README 同步检查只归一化 CRLF/LF 行尾，其他内容逐字符比较；生成器输出和内嵌案例代码统一为 LF。
- 原因：仓库启用 `core.autocrlf=true`，不同检出环境不应使内容一致的 README 构建失败。
- 影响：手工内容改动仍会阻断构建；仅行尾格式差异不触发失败。
